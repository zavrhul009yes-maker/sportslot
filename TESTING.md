# Тестовые сценарии SportSlot

## Сценарий 1. Регистрация нового пользователя
- **Начальные условия:** не авторизован, email ещё не зарегистрирован.
- **Действие:** открыть приложение → вкладка «Регистрация» → заполнить имя, email, пароль, повтор → «Создать аккаунт».
- **Ожидаемый результат:** пользователь создан, открывается «Мои записи», в шапке имя и роль «Пользователь».

## Сценарий 2. Вход обычного пользователя
- **Начальные условия:** зарегистрирован обычный пользователь.
- **Действие:** вкладка «Вход» → email + пароль → «Войти».
- **Ожидаемый результат:** открывается «Мои записи», видны только свои записи.

## Сценарий 3. Вход администратора
- **Начальные условия:** учётная запись админа создана.
- **Действие:** вкладка «Вход» → email + пароль администратора.
- **Ожидаемый результат:** открывается «Все записи», видна роль «Администратор».

## Сценарий 4. Создание записи с корректными данными
- **Начальные условия:** вход как пользователь.
- **Действие:** «+ Новая запись» → вид спорта, дата (будущая), время, тренер → «Записаться».
- **Ожидаемый результат:** зелёный баннер «Запись успешно создана!», запись в списке со статусом «Подтверждена».

## Сценарий 5. Отказ при некорректных данных
- **Действие:** «+ Новая запись» → оставить поля пустыми → «Записаться».
- **Ожидаемый результат:** под полями красные сообщения, запись не создаётся.

## Сценарий 6. Сохранение после перезагрузки
- **Действие:** создать запись → Ctrl+F5.
- **Ожидаемый результат:** запись остаётся в списке.

## Сценарий 7. Изменение состояния объекта
- **Действие:** открыть запись → отменить → подтвердить.
- **Ожидаемый результат:** статус меняется на «Отменена», кнопки исчезают.

## Сценарий 8. Бизнес-правило: запрет пересечения
- **Начальные условия:** есть активная запись на 15:00 у тренера X.
- **Действие:** попытаться создать запись на то же время с тем же тренером.
- **Ожидаемый результат:** сообщение «Этот слот уже занят», запись не создаётся.

## Сценарий 9. Новая функция: история статусов
- **Действие:** создать запись → отменить → открыть карточку.
- **Ожидаемый результат:** в блоке «История изменений» видны две записи: «создана» и «отменена».

## Сценарий 10. Новая функция: оценка тренера
- **Начальные условия:** админ отметил запись как «Посещено».
- **Действие:** пользователь открывает запись → «Оставить оценку» → 5 звёзд + комментарий → отправить.
- **Ожидаемый результат:** сообщение «Спасибо за оценку!».

## Сценарий 11. Новая функция: фильтр по 3 параметрам
- **Действие:** выбрать вид спорта + статус + сортировку.
- **Ожидаемый результат:** список фильтруется одновременно по всем параметрам.

## Сценарий 12. Админ-панель: показатели и диаграммы
- **Действие:** войти как админ → открыть «Все записи».
- **Ожидаемый результат:** 6 показателей, 2 диаграммы, работающий фильтр по периоду.

## Сценарий 13. Проверка безопасности: запрет админки
- **Начальные условия:** вход как пользователь.
- **Действие:** попытаться перейти на `adminPage` через URL или изменить роль в DevTools.
- **Ожидаемый результат:** доступ запрещён (RLS + проверка роли).

## Сценарий 14. Проверка безопасности: запрет чужой записи
- **Действие:** попытаться открыть запись другого пользователя через ID.
- **Ожидаемый результат:** RLS не возвращает данные, запись не открывается.

## Сценарий 15. XSS-защита
- **Действие:** создать запись с комментарием `<script>alert('XSS')</script>`.
- **Ожидаемый результат:** скрипт не выполняется, текст отображается как есть.

# Тестовые сценарии SportSlot

Все сценарии пройдены в локальной версии приложения (Live Server) и в опубликованной версии (после деплоя). Результаты: ✅ пройдено, ❌ не пройдено.

---

## Сценарий 1. Регистрация нового пользователя

**Начальные условия:** пользователь не авторизован. Email ещё не зарегистрирован.

**Действие:**
1. Открыть приложение.
2. Перейти на вкладку «Регистрация».
3. Заполнить поля: имя, email, пароль (≥6 символов), подтверждение пароля.
4. Нажать «Создать аккаунт».

**Ожидаемый результат:**
- Пользователь создан в `auth.users`.
- Триггер `handle_new_user` создаёт запись в `profiles` с ролью `user`.
- Пользователь автоматически входит в систему.
- Открывается «Мои записи».
- В шапке: имя пользователя и роль «Пользователь».

**Результат:** ✅ пройдено

## Сценарий 2. Вход обычного пользователя

**Начальные условия:** пользователь зарегистрирован.

2. Вкладка «Вход».
3. Ввести email и пароль.
4. Нажать «Войти».

**Ожидаемый результат:**
- Открывается «Мои записи».

- Роль в шапке: «Пользователь».
- Нет вкладки «Все записи».

**Результат:** ✅ пройдено

## Сценарий 4. Создание записи с корректными данными

**Начальные условия:** вход как пользователь.

**Действие:**
1. Нажать «+ Новая запись».
2. Выбрать вид спорта (например, «Теннис»).
3. Выбрать будущую дату.
4. Выбрать время (например, 14:00 – 15:30).
5. Указать тренера (опционально).
6. Ввести комментарий (опционально).
7. Нажать «Записаться».

**Ожидаемый результат:**
- Кнопка блокируется, текст меняется на «Сохранение...».
- Запись создаётся в `records` со статусом «Подтверждена».
- Триггер `log_status_create` добавляет запись в `status_history`.
- Показывается зелёный баннер «Запись успешно создана!».
- Новая запись появляется в списке.

**Результат:** ✅ пройдено

## Сценарий 5. Отказ при некорректных данных

**Начальные условия:** вход как пользователь, форма создания открыта.

**Действие:**
1. Оставить поле «Вид спорта» пустым.
2. Оставить поле «Дата» пустым.
3. Нажать «Записаться».

**Ожидаемый результат:**
- Форма не отправляется.
- Поля подсвечиваются красным.
- Под полями появляются сообщения:
  - «Выберите вид спорта»
  - «Укажите дату»
- Запись не создаётся.
- В Supabase → Table Editor → records — новой строки нет.

**Результат:** ✅ пройдено

## Сценарий 8. Изменение состояния объекта (отмена с причиной)

**Начальные условия:** есть запись со статусом «Подтверждена».

**Действие:**
1. Открыть карточку записи.
2. Нажать «Отменить запись».
3. В модальном окне выбрать причину (например, «Заболел»).
4. Нажать «Отменить запись».

**Ожидаемый результат:**
- Статус меняется на «Отменена».
- Триггер `log_status_change` добавляет запись в `status_history`.
- В историю записывается комментарий «Причина отмены: Заболел».
- Кнопки действий исчезают.
- Показывается уведомление «Запись отменена».
- В списке запись отображается с новым статусом.

**Результат:** ✅ пройдено

## Сценарий 9. Бизнес-правило: запрет пересечения по времени

**Начальные условия:** есть активная запись у тренера X на дату D и время T.

**Действие:**
1. Создать новую запись.
2. Выбрать того же тренера X.
3. Указать ту же дату D и то же время T.
4. Нажать «Записаться».

**Ожидаемый результат:**
- Запись не создаётся.
- Под полем «Время» появляется сообщение: «Этот слот уже занят у выбранного тренера».
- Триггер `check_slot_available` на уровне БД тоже блокирует вставку (если обойти клиент).
- Показывается красный баннер «Этот слот уже занят. Выберите другое время».

**Результат:** ✅ пройдено

## Сценарий 10. Новая функция: история статусов

**Начальные условия:** есть запись, у которой менялся статус.

**Действие:**
1. Открыть карточку записи.
2. Прокрутить до блока «История изменений».

**Ожидаемый результат:**
- Отображается список изменений:
  - «Запись создана» (статус «Подтверждена»)
  - «Подтверждена → Отменена» (с причиной)
- Каждая запись содержит дату и время изменения.

**Результат:** ✅ пройдено

## Сценарий 11. Новая функция: оценка тренера

**Начальные условия:** запись в статусе «Посещено». Пользователь — её владелец.

**Действие:**
1. Открыть карточку записи.
2. Нажать «Оставить оценку».
3. Выбрать 5 звёзд.
4. Ввести комментарий.
5. Нажать «Отправить».

**Ожидаемый результат:**
- Оценка сохраняется в `reviews`.
- Показывается зелёный баннер «Спасибо за оценку!».
- В разделе «Тренеры» средний рейтинг тренера обновляется.
- Повторная оценка той же записи невозможна (UNIQUE constraint).

**Результат:** ✅ пройдено

## Сценарий 12. Новая функция: избранные тренеры

**Начальные условия:** вход как пользователь.

**Действие:**
1. Открыть раздел «Тренеры».
2. Нажать ⭐ у любого тренера.
3. Нажать фильтр «Избранные».

**Ожидаемый результат:**
- Тренер добавлен в `favorites`.
- Звёздочка стала жёлтой (активной).
- Показывается баннер «Тренер добавлен в избранное».
- Фильтр «Избранные» показывает только избранных тренеров.
- Повторный клик по ⭐ удаляет из избранного.

**Результат:** ✅ пройдено

## Сценарий 13. Новая функция: заметки в шапке

**Начальные условия:** вход как пользователь, есть записи.

**Действие:**
1. Открыть карточку записи.
2. Нажать «📝 Добавить заметку».
3. Ввести текст.
4. Нажать «Сохранить».
5. Нажать на иконку 📝 в шапке.

**Ожидаемый результат:**
- Заметка сохраняется в `records.notes`.
- В шапке у иконки 📝 появляется счётчик (количество заметок).
- Панель заметок открывается по клику.
- В панели виден текст заметки с номером записи и датой.
- Клик по заметке открывает карточку записи.
- Пустое состояние: «Заметок пока нет».

**Результат:** ✅ пройдено

## Сценарий 14. Новая функция: расширенный фильтр

**Начальные условия:** есть несколько записей с разными видами спорта и статусами.

**Действие:**
1. Открыть «Мои записи».
2. Выбрать вид спорта в фильтре.
3. Выбрать статус в фильтре.
4. Выбрать сортировку «Сначала старые».

**Ожидаемый результат:**
- Список фильтруется одновременно по всем параметрам.
- Сортировка меняется.
- Поиск по тексту работает вместе с фильтрами.
- Пустое состояние показывается, если нет совпадений.

**Результат:** ✅ пройдено

## Сценарий 15. Административная панель

**Начальные условия:** вход как администратор.

**Действие:**
1. Открыть «Все записи».
2. Проверить показатели.
3. Проверить диаграммы.
4. Изменить фильтр по периоду (например, «Последние 7 дней»).
5. Изменить фильтр по виду спорта.

**Ожидаемый результат:**
- 6 показателей пересчитываются по данным из Supabase:
  - Всего записей
  - Подтверждено
  - Посещено
  - Отменено
  - Пользователей
  - Оценок
- 2 диаграммы отображаются корректно:
  - Столбчатая — записи по видам спорта
  - Круговая — распределение по статусам
- При изменении фильтра показатели и диаграммы **пересчитываются**.
- После перезагрузки страницы данные снова загружаются из Supabase.

**Результат:** ✅ пройдено
